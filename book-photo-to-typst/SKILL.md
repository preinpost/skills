# Book Photo → Typst PDF (오케스트레이터 워크플로)

이 스킬이 켜지면 너는 **오케스트레이터**다. 계획·결정은 네가 하고, 실제 작업(사진 판독, 텍스트 옮김, 도표 교정, 조판, 검증)은 **반드시 서브에이전트**에 위임한다. 직접 하지 않는다.

## 0. 시작 전 반드시: 서브에이전트 모델 확인

작업을 **시작하기 전에** 서브에이전트에 사용할 모델을 사용자에게 확인한다.

- 사용자가 이번 요청에서 provider / model / thinking level(또는 variant/effort)을 **이미 지정했다면** 그 값을 그대로 쓴다.
- **하나라도 빠졌으면反问한다.** 추측하거나 기본값으로 넘기지 않는다. 아래처럼 물어본다:

  > 서브에이전트로 사용할 모델을 알려주세요.
  > - provider: (예: `opencode`, `pi`, `claudeAgent` …)
  > - model: (예: `opencode/hy4-flash-free`, `meridian/claude-haiku-5-5` …)
  > - thinking level / variant / effort: (예: `high`)

- 가능한 값은 `orchestrator_capabilities`로 조회한다(최초 1회, 그 뒤 모델 변경 요청이 있을 때만 재조회).
- 사용자가 값을 주기 전에는 delegate_task를 호출하지 않는다.

`delegate_task` 호출 시:
```
target: { providerInstanceId: <확정 provider>, model: <확정 model>,
          options: { <해당 모델의 thinking/variant 옵션>: <확정 값> } }
runtimeMode: "full-access"  (별도 지정 없으면 상속)
```

## 1. 위임하지 않는 것 (오케스트레이터 직접)

- 사용자 의도·범위·완료 기준 파악, 모호하면 묶어서 질문
- 계획 수립 및 사용자 확인(작거나 방향 선택이 걸리면 스폰 전에 짧게 보여주기)
- 페이지 매핑표 확정 (아래 2절)
- 최종 결과 취합·검증·사용자 보고
- 회고 기록 (`.agents/retro.md` append)

## 2. 페이지 매핑을 먼저 확정한다 (가장 흔한 실패 지점)

사진은 보통 **한 장에 펼쳐진 2쪽(스프레드)** 이 담기고, 같은 스프레드를 **여러 각도로 2~3장씩** 찍는 경우가 많다. 파일명 순서나 IMG 번호를 페이지 순서로 착각하면 중복·누락이 생긴다.

스폰 **전에** 반드시:

1. 모든 사진 하단 푸터 영역을 크롭해 한 장의 컨택트 시트로 만든다.
2. 각 사진의 실제 좌/우 페이지 번호를 읽어 **매핑표**를 만든다.
   ```
   | 사진 | 실제 페이지 | 비고 |
   | IMG_5270 | 16~17 | 17쪽 잘림 |
   | IMG_5271 | 18~19 | ... |
   ```
3. 같은 스프레드끼리 짝지어, **잘린 페이지를 다른 각도 사진으로 보완**할 계획을 세운다.
4. 이 매핑표를 모든 서브에이전트 task에 그대로 넣는다. 각 에이전트는 "파일명이 아니라 이 표의 실제 페이지 번호를 기준으로 하라"는 지시를 받는다.

## 3. 공유 스타일 계약 (폰트/간격 편차 방지) ⭐

서브에이전트가 각자 폰트 크기·행간·여백을 조금씩 다르게 조정하면 최종 PDF에서 티가 난다. **스타일은 오직 한 곳에서만 정의**하고, 페이지 담당 에이전트는 절대 재정의하지 않는다.

### 오케스트레이터가 스폰 전에 할 일
- `ch1_style.typ`(또는 프로젝트의 공유 스타일 파일)에 스타일 함수와 `#set` 값을 **한 번만** 정의해 둔다.
- 메인 문서와 모든 페이지 파일이 **같은 스타일 파일을 import**하도록 한다.
  - Typst의 `#include`는 스코프를 상속하지 않으므로, 페이지 파일마다 `#import "ch1_style.typ": *` (또는 프로젝트 규약에 맞는 import)을 넣어야 한다. 이 import 문은 오케스트레이터가 템플릿으로 제공한다.

### 서브에이전트 task에 반드시 넣을 문구
```
[스타일 규칙 — 절대 위반 금지]
- 폰트, 글자 크기, 행간(leading), 문단 간격(spacing), 여백, 색상, 제목/배지 크기 등
  모든 스타일 값은 공유 스타일 파일(ch1_style.typ)에만 있다.
- 너는 #set text / #set par / #set page 를 쓰지 마라.
  size:, leading:, spacing:, fill: 값을 직접 지정하지 마라.
- 스타일 함수(h1, h2, quote, sign, sec-badge 등)는 정의하지 말고
  공유 파일에서 import해 사용만 하라.
- 분량이 2쪽을 넘어도 행간을 줄이지 마라. 대신 오케스트레이터에게
  "분량 초과"로 보고하고 페이지 분할/재배치를 맡겨라.
- 도표 이미지는 image("...", width: 100%)만 사용하고 크기/정렬을 임의 조정하지 마라.
```

### 편차가 생기면
검증 단계에서 `grep -rn '#set par\|leading:\|size:' spread_*.typ` 로 재정의를 찾아낸다(이전 실제 사례: `spread_18_19.typ`의 `leading: 9.5pt`, `spread_28_29.typ`의 `leading: 10pt`). 발견하면 해당 파일을 **공유 스타일을 따르도록** 되돌리고 재컴파일한다. 스타일 값을 더 예쁘게 바꾸려는 유혹을 피하고, 변경이 필요하면 오케스트레이터가 공유 스타일 파일에서 **모든 페이지에 동일하게** 적용한다.

## 4. 병렬 스폰

- 독립적인 페이지 작업은 한 턴에서 동시에 스폰한다.
- 같은 파일 동시 수정을 피하도록 각 에이전트의 산출 파일 경로를 명시적으로 분리한다(예: `ch1_p16.typ` vs `ch1_p18.typ`).
- 스폰 호출이 에러로 끝나도 에이전트가 실제 생성됐을 수 있으니, 같은 task로 바로 재스폰하지 말고 파일/스레드 생성 여부를 먼저 확인한다.
- 완료 알림을 기다린다. 실행 중 폴링하지 않는다.

### task 작성 필수 요소
서브에이전트는 부모 대화를 모른다. task 문자열만으로 끝나는 독립 지시를 쓴다:
- 목표 (계획의 어느 조각인지)
- 컨텍스트: 절대경로, 원본 사진 경로, 공유 스타일 파일 경로, **페이지 매핑표**
- 범위: 만들 파일 / 건드리면 안 되는 파일(메인 문서, 다른 페이지, 원본 사진)
- 스타일 규칙 (3절 문구 그대로)
- 완료 조건 + 화면 캡처 경로 보고
- 결정 규칙: 계획에 없는 판단이 필요하면 임의로 결정하지 말고 멈춰 보고

## 5. 취합·검증 (오케스트레이터 직접, 또는 review 에이전트)

- 같은 스프레드의 중복 파일을 짝지어 더 완전한 버전으로 합친다(잘린 부분 상호 보완).
- `#include`로 순서대로 붙이고, 페이지 번호가 연속인지 확인한다.
- `typst compile` → `pdfinfo`(페이지 수) → `pdftotext`(페이지 번호 연속) → `pdfimages -list`(도표 삽입) → 대표 페이지 렌더링 캡처.
- 보고에는 검증 상태를 `검증됨(증거 있음)` / `미검증` / `실패`로 구분한다.
- 사용자가 보게 될 화면 캡처 경로를 반드시 첨부한다.

## 6. 보고 + 회고

마지막 보고에 포함:
- 각 하위 작업에 어떤 provider/model/thinking을 썼는지
- 각 결과와 검증 상태, 실패·건너뛴 항목
- 화면 캡처 경로
- 남은 일 / 사용자 결정 필요 사항

회고는 묻지 않고 `.agents/retro.md`에 한 줄 append한다:
```
- YYYY-MM-DD | 막힌 점 | 다음엔: 바꿀 점 | 승격후보: 없음/AGENTS.md/스킬
```
같은 교훈이 2회 이상 반복되면 사용자 승인을 받아 AGENTS.md 또는 이 스킬로 승격을 제안한다.

## 참고: 이 스킬의 실제 유래 (검증된 수치)

- 조판: A4, `KoPubWorldDotum` 10.5pt, `leading 13.25pt + spacing 21pt` (= 실제 줄간격 18.5pt / 문단간격 26.5pt, ReportLab 초기본과 동일).
- 인용문 `block`은 `par.spacing`을 무시하므로 `above/below: 21pt` 직접 지정.
- 목차: 행 피치 27pt, 선 0.25pt `#dddddd`, 좌우 inset 8.5pt.
- 도표 기울임 교정: PIL `Image.Transform.QUAD`, 꼭짓점 순서 **좌상→좌하→우하→우상**, `resample=BICUBIC, fillcolor='white'`.
- 페이지 시작 번호 보정: `#counter(page).update(<원본 첫 페이지>)`.
